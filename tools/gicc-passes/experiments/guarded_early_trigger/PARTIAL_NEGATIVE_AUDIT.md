# Guarded early-trigger partial-negative audit

This is a post-failure, one-sided audit.  It cannot rescue an incomplete scout
as a positive result and it cannot turn completed timings into paper evidence.
It may only prove that the preregistered positive gate is mathematically
unreachable from the completed, correctness-checked pairs.

For each size, replace the sole missing speedup with an arbitrarily favorable
value.  The candidate remains negative when either the largest possible win
count is below three or the largest possible four-pair median is below 1.02.
Every observed pair must first pass the original 16-rank checksum and launch
count checks.  The audit also requires a clean `pdebug` scheduler record and a
nested-step refusal caused by the fixed step duration exceeding the remaining
outer allocation lifetime.

The frozen monitor also accepted only plain-decimal timing text, while the
benchmark emitted scientific notation at these sizes.  This audit uses the
same timing, warmup, checksum, and launch-count invariants with a numeric
grammar that accepts either notation.  It does not alter the frozen monitor or
claim that the original run passed it.

The output keeps `guarded_early_trigger` model-invisible and skips its
confirmation.  A full performance estimate would require a fresh,
independently frozen rerun; this audit does not request one.
